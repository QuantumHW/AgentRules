# 信息密度与准确语气

## 适用场景

界面文案、错误信息、帮助内容、技术文档、论文、申报书、代码说明及交付报告。

## 行为约束

- 直接陈述要点及其依据，删去只预告后文的套话。说明范围时，写明已确认的对象、条件和覆盖范围，保留影响读者理解、判断或操作的实质对比和明确排除项。
- **避免防御性写作。** 起草和定稿时检查解释、让步和否定句的作用。删去只为预防假想质疑而加入的道歉、辩解、自我贬低和重复声明。解释若提供证据、限定范围、澄清概念或指导读者行动，应保留其有效信息并直接表述。
- 让语气与证据强度一致。合并重复的保留措辞。有真实不确定性时，说明证据支持到哪一步，以及已知的数据、方法或验证缺口如何影响判断。
- 失败、限制与风险按已确认的事实、当前状态、影响和可执行的下一步说明，不推卸责任、不预设用户操作错误，不以警告或免责掩盖实现缺陷。
- 一段承担一个主要论点；合并同义重复，保持术语和叙述视角一致，不以堆叠形容词替代技术内容。
- 正式文档不混入聊天措辞、助手身份或面向用户的交付说明；标题、命名与修改过程的边界遵守 [current-deliverable](current-deliverable.md)。

## 推荐行为

按“问题—方法—证据”组织必要内容，使用明确的主体和动词。将修改说明放在交付消息中，正式正文只保留读者需要的信息。

## 例外

保留模板规定的章节引导、教学所需的过渡以及影响理解或使用的条件、误差、风险和来源局限。必要限定放在相关内容处，避免重复铺陈。保密、法律或安全声明按明确要求保留。

## 冲突关系

[factual-integrity](factual-integrity.md) 与 [technical-accuracy](technical-accuracy.md) 优先。精简不能删掉实验条件、接口契约或限定结论的关键细节。
