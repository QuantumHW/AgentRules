# IssueDesk 维护规范

## 项目与职责

本文件采用虚构演示背景：IssueDesk 是 Python 3.12 / FastAPI 工单服务，使用 SQLAlchemy 和 SQLite；以下路径、命令和契约是示例设定，不代表 AgentRules 仓库，也不能当作其他项目的已确认事实。

- `app/api/` 定义 HTTP 路由、请求模型、身份校验及响应转换，不直接组织持久化查询。
- `app/services/` 实现工单状态流转和业务规则，通过 `app/repositories/` 访问数据库。
- `app/repositories/` 封装 SQLAlchemy 查询与持久化；`app/models/` 定义数据库模型；不要在多个层次维护同一份状态。
- `tests/` 覆盖 API 契约及状态流转。根目录 `pyproject.toml` 声明依赖和 pytest 配置，`uv.lock` 固定依赖版本。

## 实现边界

- 只实现用户要求的功能及必要关联修改。修复状态流转不授权添加通知、权限系统或更换数据库。
- 沿用现有分层和依赖；没有当前复用需求时，不为单个工单操作创建通用工作流引擎、插件接口或可配置状态机。
- 保持已有响应字段和状态码契约；确需改变时同步直接调用方、文档及测试。不凭空添加兼容层。
- 新增依赖须解决当前需求；同步 `pyproject.toml` 与 `uv.lock`，不顺带升级其他包。

## 错误处理

- 外部请求由 API 层的请求模型校验；服务内部收到已验证对象后不重复检查相同类型和必填字段。
- 工单不存在返回 404，不允许的状态转换返回 409；沿用已有业务异常与 API 映射，不用空对象或 200 响应掩盖失败。
- 保留事务回滚及资源清理。只在能恢复或转换已知错误的边界捕获异常；意外失败保留诊断信息，日志不记录认证信息。
- 对写操作新增重试前确认幂等性和可恢复故障条件；不得无差别重试所有异常。

## 修改与验证

- 修改前阅读相关路由、服务、仓储和测试，保留用户改动；不重排无关文件。
- 在项目根目录、依赖已安装的环境运行 `uv run pytest`；可先运行相关测试，影响公开 API 或状态流转时运行完整测试集。
- 缺陷修复验证原触发条件及必要错误路径，不仅断言内部实现细节；纯文字改动无需新增代码测试。
- 报告实际执行的检查和结果；未执行测试不得声称通过，新增能力不得仅凭代码存在就声称已部署可用。
