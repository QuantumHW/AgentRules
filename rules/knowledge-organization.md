# 维护知识资产与关联

## 适用场景

长期维护的个人笔记、学习资料、文献笔记和知识库。普通软件 README 或一次性文稿不因使用 Markdown 就自动适用。

## 行为约束

### 内容与组织

- 新建笔记前检查相关主题是否已有承载位置，优先补充合适的现有笔记；不要为一次性问题或同一概念制造大量重复、空泛的笔记。
- 以检索、概念关联和长期复用为整理目标，不以扩写字数或增加文件数量代替整理。拆分长文、建立索引或合并笔记须解决实际组织问题，并在授权范围内执行。
- 保留重要原文、技术含义、证据和必要细节；不得借排版或摘要压缩悄然改变原观点。发现疑似错误时说明位置、依据和修订建议，未获相应修改授权时保留原文，不将其继续当作已核实结论。
- 文件名应能识别主题并沿用已有命名习惯；不要为了统一风格批量重命名。确需移动、重命名或合并时核对入链、出链、附件引用及目标冲突。

### 链接与属性

- 使用知识库已采用的链接语法。添加关联前查找真实目标，区分同名笔记，并核对用到的标题或块标识；不批量制造无目标链接，不创建重复概念来凑齐关联。
- 沿用已有 YAML 属性名、类型、模板和插件需求，不擅自把 `describe` 改成 `description` 或另建同义字段。补齐属性只发生在获授权的新建、整理或维护任务中，不顺带扫描改写全库。
- 表示首次创建时间的字段不得在后续编辑时刷新为修改时间。优先依据可信的创建记录；文件系统时间只有在能代表原始创建时间时才可使用，复制或导入时间不能直接充当来源。未知时间留空，已有证据仅精确到日期时不得补造时分秒。
- 标签与摘要必须来自实际正文或大纲，不添加未证实内容。沿用已确认的标签类型；项目采用标签列表时保留列表结构，空白笔记可暂留空，形成内容后再补齐。
- 有既存标签索引时先查阅并复用语义准确的标签，避免同义冗余；没有索引时按需查看相关笔记，不擅自建设新索引系统。任务改变了实际标签且索引维护属于授权范围时，同步更新索引中的计数和笔记关联，只收录真实使用的标签。

### 归档与恢复

- 区分用户要求交付的正式笔记与 Agent 工作记录。正式笔记按用户指定位置归档；未指定时参照同主题目录，缺少分类依据时使用已确认的知识库根目录，不仅因工作区可写就将正式成果放入其中。
- 工作区、正式区、规则文件的操作权限按项目既有规范分别确认；规则讨论不授权实际整理知识库，小范围格式修复也不豁免目标文件的操作授权。
- 未明确授权的批量移动、目录重构、合并或大范围删改，先列出原因、影响文件、预期变化和链接风险，等待决定。已明确批准的具体操作按批准范围执行，不重复请求同一许可。
- 不主动删除笔记来“清理”知识库。用户明确要求删除时，默认使用项目已确认的可恢复回收机制，核对准确路径且不覆盖回收站同名文件，并报告恢复位置。未确认回收机制时先确定可恢复方案，不以永久删除代替；清空回收站或永久删除须有针对该操作的另行明确授权。

## 推荐行为

先查现有主题、模板、标签和目录，再提出最小整理方案；完成授权操作后检查内容语义、属性、链接、索引与归档位置的一致性。只为生成规范时发现必要约定，不实际改动笔记或更新索引。

## 例外

用户明确要求的独立笔记、草稿或计划链接可以创建，空白笔记可以暂留空属性；不要把既有合法的未解析链接一律清除。用户明确要求改写观点、合并内容或指定交付路径时按要求执行，仍保留事实依据与必要恢复手段。必要的技术限定不因精简而删除。

## 冲突关系

[scope-control](scope-control.md) 决定操作授权，[factual-integrity](factual-integrity.md) 决定内容与时间的证据要求。保留原文不等于认可错误；[concise-writing](concise-writing.md) 不授权删减必要专业内容。具体标题层级、字段、语言和路径由项目规范确定，不能推广成全部 Markdown 项目的强制要求。
