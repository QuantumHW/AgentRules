AgentRules 是一个轻量级、基于项目上下文的 `AGENTS.md` 智能脚手架。它通过可复用的行为规则和 `generate-agents` Skill，分析项目已有材料与实际需求，生成结构清晰、可直接使用、便于调整的 AI 工作规范，减少为每个项目重复编写提示词的成本。

规则与生成结果面向所有能够读取并遵循 `AGENTS.md` 的 Agent；Skill 的安装、发现与调用方式由具体工具决定。

## 为什么需要 AgentRules？

`AGENTS.md` 为支持它的 Agent 提供项目级工作指导，记录项目约定、修改边界和验证要求。为每个项目从头编写规范，往往需要反复处理相似的问题：

- **过度防御**：针对未经证实的异常场景添加宽泛捕获、静默回退或重复校验。
- **过度设计**：擅自增加抽象层、配置项和未经要求的功能，使简单任务复杂化。
- **冗余表达**：在文档中加入大量过程性说明、自我辩解和缺乏信息价值的套话。
- **内容失真**：虚构技术细节、参考文献或实验数据，将未经验证的推测写成事实。
- **范围失控**：修改无关文件、扩展任务，偏离原始需求。

AgentRules 将这些共通问题整理为可复用的规则，根据项目证据选择和组织约束。必要的错误处理、安全校验、技术条件和真实风险仍应保留。

**无需从零编写，也不必直接套用千篇一律的固定模板。**

## 核心功能

### 基于项目上下文生成规范

由 Agent 读取相关的项目说明、目录、依赖配置、现有指令和任务资料，选择适用规则并处理重复与冲突。只有已确认的技术栈、路径和命令才会写入规范；信息不足时，生成有依据的最小约束，不补造项目架构。

规则库使用 **Rules** 组织行为主题，通过 **Profiles** 组合项目场景，由 **Skill** 执行分析、选择和生成流程。用户不需要手动挑选和拼接规则文件。

### 支持多种项目场景

| 项目类型 | 主要约束方向 |
| --- | --- |
| 软件开发 | 避免过度设计、合理处理异常、控制修改范围、验证代码行为 |
| 通用文档 | 内容准确、表达精简、结构清晰、术语一致 |
| 科研论文 | 学术表达、引用可核验、实验数据与结论一致 |
| 项目申报书 | 模板遵循、技术路线与指标对应、研究基础与成果真实 |
| 个人笔记与知识库 | 知识去重与关联、属性和标签一致、正式归档、授权边界与可恢复删除 |

同一项目可以组合多个场景。例如源码、论文与手册共存时，分别规定代码验证、研究证据和文档表达要求，并合并共通约束。

### 保留已有项目约束

已有 `AGENTS.md` 会先被完整读取。用户明确要求更新时，流程保留有效的手工规则和项目专属信息，整合适用条款；无法安全决定的实质冲突交由用户选择。仅要求生成而未授权更新时，提供候选内容或差异，不直接覆盖原文件。

### 成品直接呈现当前内容

约束修改后的标题、文件名、界面和正文沿用正式表达，不因删改自行添加“精简版”“去除 XX 后的版本”等标签，也不在成品中留下删除声明。正式产品分类、用户指定名称、真实能力限制和明确要求的变更记录分别按其用途处理。

### 用自然语言完善规则

在本地 AgentRules 仓库中，向遵循仓库维护规范的 Agent 描述问题和期望行为，即可请求合并、修改或新增规则，无需掌握专门的配置语法。具体用法见下文“让规则库不断完善”。

## 快速开始

### 1. 安装

在你使用的 Agent 软件中，打开允许联网和本地文件操作的会话，发送：

```text
请从 https://github.com/QuantumHW/AgentRules 安装 AgentRules，供当前 Agent 在不同项目中使用。

请将完整仓库保存到持久的本地目录，保留 skills/generate-agents、rules/ 和 profiles/ 的相对结构，不要只复制 SKILL.md。
如果当前 Agent 支持 Agent Skills，请按它实际支持的方式注册 generate-agents；如果不支持，请告诉我本地 SKILL.md 的路径，以及如何让当前 Agent 直接读取并执行该流程。
如果已有同名安装，请先检查能否复用，不要直接覆盖。完成后检查入口与规则资源是否可读，并告诉我安装位置、可用的调用方式和实际检查结果。
```

Agent 负责下载、配置和检查，用户无需手动克隆仓库或执行命令。保留完整仓库，避免移动或删除后使资源引用失效。未注册为 Skill 时，在后续请求中附上安装时返回的本地 `SKILL.md` 路径，让 Agent 读取并执行。

以 Codex 为例，可将仓库中的 `skills/generate-agents` 软链接到 `~/.agents/skills/generate-agents`；具体加载方式见 [OpenAI 官方 Skill 文档](https://learn.chatgpt.com/docs/build-skills)。其他 Agent 使用各自的配置方式，各平台安装与加载需分别验证。

### 2. 为项目生成 AGENTS.md

在目标项目中打开 Agent，提供已有 README、需求、源码、模板或其他相关材料，然后输入：

```text
使用 AgentRules，分析当前项目，并为我生成一份适用的 AGENTS.md。
```

支持 Skill 显式调用的工具可使用对应语法。例如在 Codex 中：

```text
$generate-agents 为当前项目生成 AGENTS.md，以现有项目资料为依据。
```

Agent 按流程分析资料、选择场景并生成规范。审阅其中的项目事实、工作边界和验证要求后，用于后续任务。空目录也可使用，但不会获得猜测的技术栈或测试命令。

### 3. 按需调整

继续用自然语言提出当前项目的要求，例如：

> 更新当前 AGENTS.md：这个项目用于科研原型验证，没有历史版本兼容要求，请精简相关约束，保留必要的正确性和安全要求。

> 更新当前 AGENTS.md：这是正式技术文档项目，请重点约束技术指标的事实依据，并删除无必要的过程性和防御性表述。

已有文件可明确请求合并更新：

```text
使用 AgentRules 更新当前 AGENTS.md，保留手工编写的命令和项目约束，合并适用规则。
```

## 使用示例

### 软件开发

针对 Python Web 服务，要求规范代码实现与修改范围：

> 使用 AgentRules 为当前项目生成 AGENTS.md。重点约束过度设计、无意义的异常处理，以及超出需求的功能扩展。

规范应以已有架构、接口和测试入口为依据，不仅凭“Python Web 服务”就补造数据库、目录或部署流程。

### 科研论文

针对论文项目，要求准确、精练地表达研究内容：

> 使用 AgentRules 为当前论文项目生成 AGENTS.md。要求数据和引用有可核验来源，实验结果与结论一致，学术表达准确精练，保留必要的适用条件与局限。

规范侧重研究证据和贡献声明，不会把未开展的实验写成既有结果，也不会把代码测试通过当作论文结论的证明。

### 项目申报书

针对已有 Word 模板与补充材料的申报项目：

> 使用 AgentRules 为当前申报书项目生成 AGENTS.md。必须遵守现有模板和补充资料，不得编造研究成果或技术指标，避免冗余、过程性和自我辩解式表达。

规范侧重模板、材料依据、研究内容与考核指标的一致性。生成规范本身不修改申请书。

### 个人笔记与知识库

针对 Obsidian 或其他长期维护的 Markdown 笔记库：

> 使用 AgentRules 为当前知识库生成 AGENTS.md。保留已有观点和专业细节，避免重复建页，遵守现有属性、标签和链接规范，区分正式笔记与工作记录，并明确批量整理和可恢复删除的授权边界。

规范依据当前知识库的实际约定生成，不会将固定字段、无一级标题或某个工作区路径强加给其他项目；生成规范本身不修改笔记库。

混合项目可在请求中说明“同时覆盖源码、论文和使用手册，并区分各自作用范围”。可参考[软件示例](examples/software/AGENTS.md)、[申报书示例](examples/proposal/AGENTS.md)和[知识库示例](examples/knowledge-base/AGENTS.md)；这些示例均采用明确标注的虚构演示背景。

## 让规则库不断完善

项目专属要求可直接调整目标项目的 `AGENTS.md`。希望在多个项目中复用的偏好，则在安装得到的本地 AgentRules 仓库中向 Agent 提出，例如：

> 请完善通用文档规则：修改已有文档时，应优先保持原有结构和写作风格，除非用户明确要求，否则不得重构整篇文档。先检查现有规则，避免重复添加。

仓库维护规范要求 Agent 检查已有内容，判断是合并、修改还是新增，并维护对应的场景引用。你只需描述问题与期望结果，无需手工编辑每个规则文件。

这会修改本地规则库；不会自动发布到上游仓库，也不会自动同步到已经生成的项目规范。

## 使用说明

- **规范需要审阅。** `AGENTS.md` 提供持续的工作指导，实际遵守程度取决于 Agent 及其指令加载方式，不是执行保证。
- **以项目证据为依据。** 未确认的技术细节、测试命令、研究结果和项目背景不能自行补成事实；必要的校验与事实限定不能因追求精简而删除。
- **规则更新不自动同步。** 本地规则库变化后，需要明确请求合并更新目标项目的 `AGENTS.md`。
- **区分规则与加载支持。** 规则面向支持 `AGENTS.md` 的 Agent；Skill 的发现、调用和指令优先级按具体工具处理，不代表所有平台均已验证。
