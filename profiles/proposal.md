# proposal：项目申报书

适用信号：存在申报指南、申请书模板、任务书或申报材料，目标是编写或修订技术研发项目申报书。

## 引用规则

- [core](../rules/core.md)、[factual-integrity](../rules/factual-integrity.md)、[scope-control](../rules/scope-control.md)。
- [concise-writing](../rules/concise-writing.md)、[technical-accuracy](../rules/technical-accuracy.md)。
- 任务确含系统方案设计且存在扩展冲动时，补选 [anti-overengineering](../rules/anti-overengineering.md)；不引入软件错误处理要求。

## 场景补充

- 以有效申报指南和模板为约束，覆盖要求的栏目、内容、篇幅和附件；不擅自删除栏目或改写固定表头。
- 建立“研究内容—关键问题—技术路线—考核指标—验证方式—交付成果”的对应关系；指标应有已提供的口径、单位与考核条件，不自行承诺数值。
- 区分研究基础、已有成果、拟开展研究和预期成果；禁止虚构人员、合作关系、设备、知识产权、实验结果和应用证明。
- 核对预算、周期、工作量、人员分工和交付要求的一致性；缺失信息列为待补，不代替用户做资金或合作承诺。
- 使用明确的技术陈述，删除空泛的过程引导与自我辩解；保留指南要求的风险分析、适用条件和事实限定。
- 沿用材料中的术语、编号、图题和文风，仅修改授权章节及必要关联引用。正式文稿中不混入修改说明。

## 组合边界

可与 documentation 组合处理格式，与 academic 组合处理研究证据。去重后保留申报专属的指南覆盖、指标映射和预算交付约束，不把计划指标写成实测成绩。
