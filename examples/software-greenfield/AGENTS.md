# Breeze 开发规范

## 目标与依据

本文件采用虚构演示背景：Breeze 项目目前只有根目录的 `需求与技术设计文档.md`，要求实现可本地导入照片、保持比例展示的响应式纯前端网页；尚未建立源码工程、Git 仓库或版本策略。以下约束指导后续开发，不代表功能已经实现。

- 开发前读取需求文档相关章节；保留纯前端、本地处理照片及响应式布局的范围。详细需求以原文为准，不在本文件重复维护。
- 不擅自增加账户、远程图片服务或后端；用户当前请求确定实际实施范围。
- 技术栈、目录、依赖和脚本以随后确认的设计及实际配置为准；不将建议当作已安装工具或现有命令。

## 通用开发约束

- 先检查需求中的错误前提、技术冲突与缺失信息；说明依据和影响，继续可独立确定的工作。
- 修改前理解相关结构、接口和数据流，保护用户改动；仅修改当前目标及必要关联内容，不顺带重构或扩展功能。
- 优先采用满足当前需求的简单方案，不为假设中的未来需求引入框架、抽象或兼容层。工程建立后沿用有效结构及锁文件流程，新增依赖必须有当前用途。
- 在用户文件、解码及浏览器资源边界进行必要校验；按真实处理策略报告错误，不吞异常或伪造成功。内部有效契约不重复堆叠兜底。
- 照片保持本地处理，不记录敏感正文或凭据；替换和卸载时清理不再使用的对象 URL、监听器及其他资源。
- 正式页面、标题和文件名表达当前产品内容，不夹带“精简版”等修改过程标签；必要的能力限制和错误信息如实保留。

## 验证与交付

- 工程建立后从实际配置确认开发、检查、测试和构建入口，不预写尚不存在的脚本命令。
- 根据变更风险验证受影响行为及必要错误路径；图片导入、比例显示和响应式布局需要浏览器检查，构建成功不能替代交互验证。
- 区分已实现、已验证和未验证；没有执行的检查不得声称通过。交付说明涉及文件、完成项、实际检查、遗留问题和下一步。

## Git、进度与版本

- 存在 Git 仓库时，开工确认仓库与分支并检查工作区、暂存区和未追踪交付文件；交付前复核差异，保护用户已有改动。
- Git 操作遵守实际授权；生成规范或完成开发不等于授权初始化仓库、暂存、提交、推送、配置远程或联网同步。
- 已有项目进度、决策或交接记录时先读取，再结合实际文件核对；维护记录时保留真实历史，不把尚未执行的计划标记为完成。
- 涉及功能交付时核对已有版本策略、权威字段和更新权限。需求中的目标版本不代表已发布版本；不自动创建版本字段、机械递增版本或启动发布。
