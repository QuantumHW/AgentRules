# 研究笔记库维护规范

本文件采用虚构演示背景：这是一个中文 Obsidian 知识库，`notes/` 保存概念与学习笔记，`papers/` 保存文献笔记，`Agent-Workspace/` 保存 Agent 工作资料，`Agent-Workspace/标签索引.md` 维护标签，库内 `.trash/` 用于可恢复删除。项目模板明确采用文件名作为笔记一级标题，并使用 `tags`、`date`、`describe`。这些设定不是 AgentRules 仓库事实，也不代表其他知识库的配置。

## 内容与结构

- 新建前查找相关主题，优先补充合适的已有笔记；不为一次性问题重复建页，不用扩写字数代替知识整理。
- 保留重要原文、技术观点、证据和必要细节。疑似错误说明位置与依据；未获相应修订授权时保留原文并提出建议，不将未经确认的原说法当作已验证结论。
- 默认中文，保留准确的英文专业术语，必要时首次给出释义；不将严谨技术内容改成口语化总结。
- `notes/` 和 `papers/` 中的笔记正文不重复写 `#` 标题，从自然段或 `##` 开始，后续层级连续；此要求不适用于本规范文件及代码示例。
- 沿用具有明确主题的简洁文件名；不要为了统一风格批量重命名。
- 笔记名与正文直接表达当前知识内容；编辑或删除一节后，不新增“精简版”“不含 XX”等修改标签，也不留下删除声明。正式历史记录或用户指定名称按既有约定处理。

## 属性与关联

- 新建笔记在开头使用 YAML 属性区；获授权整理现有笔记时，按内容补齐缺失的 `tags`、`date`、`describe`，保留合法插件字段，不另建同义属性。
- `tags` 使用 YAML 列表，填写前查阅标签索引，优先复用语义准确的现有标签；空白笔记可以暂用 `tags: []`，正文或大纲完成后再补齐相关标签。
- `date` 表示首次创建时间，后续编辑不刷新。可靠记录精确到分钟时沿用该精度，未知则留空，不填当前时间或范例日期；只有日期的证据不能补成虚构时间。
- `describe` 只概括现有正文或大纲，尚无可概括内容时留空，形成内容后补齐。
- 使用 `[[目标]]` 前查找实际笔记并区分同名目标；新增标题或块链接时核对标识。避免重复概念和批量空链接，不擅自清除用户有意保留的计划链接。
- 改动实际标签时同步维护标签索引中的使用次数与笔记关联；索引不收录候选标签。移动或重命名时检查入链、出链和附件引用。

## 归档与授权

- 用户明确要求创建正式笔记时，授权覆盖该笔记及必要标签索引维护；按指定路径交付，未指定时参照同主题目录，无分类依据时放在库根目录，不自动放入 Agent 工作区。
- 只有草稿、工作记录、整理方案、辅助资料或用户指定的内容才放入 `Agent-Workspace/`。工作区可写不授权顺带修改 `notes/`、`papers/` 等正式内容。
- 已有笔记的新增、修改、移动和删除均限于用户明确授权的目标；小范围格式修复不豁免授权。仅讨论规则时不开展实际知识库整理。
- 未明确批准的批量移动、目录重构、合并与大范围删改，先提供原因、影响文件、预期变化和链接风险。已批准的具体方案在原范围内执行。
- 不主动删除笔记。用户明确删除时，核对准确路径后移入库根 `.trash/`，采用不覆盖已有文件的名称，并报告恢复位置；永久删除或清空回收站需要另行明确授权。
- `Agent-Workspace/AGENTS.md` 是受保护的权限规则文件，须先获得用户对修改该文件的明确批准；工作区写入权限不包含自主修改它的权限。

## 核查

- 不编造文献、实验、指标、来源或笔记内容；待核实信息清楚标注，不为完整性填入猜测。
- 在授权范围内核对内容语义、YAML、标题层级、链接、标签索引及归档位置。报告实际检查与未验证部分，不把规范生成说成完成了笔记整理。
