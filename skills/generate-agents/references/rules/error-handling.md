# 按真实边界处理错误

## 适用场景

代码的输入校验、异常处理、重试、降级和错误报告；不用于约束普通文档语气。

## 行为约束

- 在外部不可信输入、权限检查、文件或网络 I/O 等真实边界执行必要校验；明确由哪一层负责。
- 已有接口、类型或上游契约能保证有效性的内部数据，不重复添加无依据的空值检查、类型判断或兜底分支。
- 只捕获能够恢复、转换为明确契约错误或补充必要上下文的异常；不要捕获后忽略、返回伪造的成功值或掩盖根因。
- 重试仅用于已知可恢复故障，受次数或时间限制，并检查操作是否幂等；不要对所有失败无差别重试。
- 不记录凭据或敏感正文；错误信息应足以定位边界和失败原因。

## 推荐行为

沿用现有错误类型与传播路径。在服务入口把已知业务失败转换为约定响应，保留意外失败的可观测性，并验证调用方能识别失败。

## 例外

任务隔离、事务回滚、资源清理或进程最外层可需要宽泛捕获；必须保留失败语义及诊断信息。只有用户需求或既有契约明确允许时才降级，且不能把部分结果表示为完整成功。

## 冲突关系

[anti-overengineering](anti-overengineering.md) 不取消安全校验、资源清理或真实恢复路径。[scope-control](scope-control.md) 限制的是无关扩展，不是完成正确处理所必需的修改。
