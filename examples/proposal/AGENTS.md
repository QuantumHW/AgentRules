# 工业设备故障诊断研发项目申报材料规范

## 材料与范围

本文件采用虚构演示背景：申报方向为工业设备故障诊断技术研发；`materials/guide.md` 是申报指南，`templates/application.docx` 是固定模板，`drafts/application.docx` 是申请书工作稿，`evidence/` 保存用户提供的研究基础材料。这些设定不代表 AgentRules 仓库或真实申报项目。

- 以指南和固定模板为准，保留既有章节、编号、表头、字数限制及附件要求。
- 只修改用户指定章节及保证一致性所必需的交叉引用。用户仅要求检查时，不修改申请书、样式或分页。
- 写作前读取目标章节填写提示及相关原始材料；当前要求与指南或模板出现冲突时说明具体影响，不静默覆盖。受保护章节的一致性问题在交付说明中报告，不越权修改。
- 保留模板列宽、页面设置、页眉页脚、页码和样式。获授权编辑前保留可恢复原件，沿用指定工作稿；辅助材料存放位置须先由项目确认，不另建多个并行终稿。
- 保留原有有效事实和用户修改；发现依据矛盾或重要规则冲突时先指出具体位置，不静默覆盖。

## 技术内容与考核

- 研究内容围绕故障数据治理、诊断模型和验证方案展开；每项指标应能对应到研究任务、技术机制、验证条件和交付成果。
- 现状分析比较其他团队方法的验证范围和局限；研究内容说明研究什么，技术方案说明如何实现，关键技术与解决途径逐项对应，不复制段落后换标题。
- 指标值、数据规模、故障类别和评测口径以指南及已确认材料为依据。缺少数值时不自行承诺准确率、时延或样本量。
- 每项指标说明输入、环境、计算方法与通过条件；相对提升给出基准。指南或专项要求未读全时，不宣称覆盖完成。
- 数据去重并按来源或相关任务合理划分训练、开发验证和独立测试；配置选择与最终测试分开。对比模型时明确控制条件和必要消融，不把采用现成模型本身称为创新。
- 技术路线说明数据获取、方法实现和验证之间的关系；不得用“智能化平台”“先进算法”等概念替代实际机制。
- 区分已有研究基础、拟开展工作和预期成果。不得虚构设备条件、合作单位、知识产权、实验结果、应用案例或获奖记录。
- 核对预算科目、研究周期、工作量、人员分工和交付物的一致性；未经提供与确认的信息保留为空或使用模板允许的待补标记，不自行作资金与合作承诺。
- 成果写清载体与已确认数量，进度按模板及技术依赖安排；未确认的合作关系不写成无合作，不擅加专利、周期或固定结项措辞。

## 写作与格式

- 沿用已有术语、图题和文风；同一概念不在“故障诊断”“故障检测”等不同技术含义之间随意替换。
- 直接陈述技术问题、研究方法和预期产出；删除“下面将介绍”等过程性引导、同义重复和不增加事实的自我辩解。
- 对已确认事实采用明确表达；对规划使用计划语态，保留指南要求的风险分析及结论成立的条件。不把预期指标写成实测结果。
- 不在正式正文插入助手身份、修改说明或聊天措辞；证据缺口集中在交付说明中报告。
- 以申请团队为主体叙述，成员共同成果保留准确机构及产权归属；不以个人履历堆砌研究基础。填写后替换示例，固定填报说明按模板保留。
- Word 使用原生段落、编号、表格和内嵌图片，不残留 Markdown 标记；图示术语、流程、图题与正文对应，绘图工具按实际要求选择。
- 沿用申请书的正式文件名与标题，删除内容后直接衔接剩余正文；未经明确指定，不另命名为“修订版”“去除 XX 后的版本”，也不保留解释删除行为的占位文字。

## 核查要求

- 核对修改章节与研究任务、指标表、进度安排、预算和成果表的一致性，不擅自扩展成全文修订。
- 引用须能定位原始材料或文献，核对其支持范围；不得补造题名、作者、年份或标识符。
- 读取支撑关键论断的原文，不用链接、标题或摘要冒充核验；区分预印本与正式发表，保留原验证场景。已核验且未变化的来源可复用记录，来源记录不混入正文。
- 修改 Word 工作稿后核对标题、表格、图题、交叉引用和实际分页；以 Microsoft Word 原生显示为最终版面依据。未完成原生检查时如实报告，不声称版面已验证。
- 内容增长允许自然分页；需要固定分页时使用 Word 分页或段落控制，不用大量空段落占位。交付前检查文字裁切、正文隐藏、图题分离和表格意外合并。
- 内部检查问题、目标、内容、技术、指标、成果与进度的对应关系；指南、指标或基本信息仍有关键缺口时，不宣称申请书已满足提交条件。
